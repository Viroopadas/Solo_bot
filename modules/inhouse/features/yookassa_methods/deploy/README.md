# Установка кнопок оплаты

Это дополнение к уже установленному SoloBot, а не установка бота или серверов с нуля.
В бота идёт папка `modules/inhouse/`; на российский сервер — четыре файла страницы
из этой папки `deploy/` и отдельный блок Caddy. В Caddy бота добавляются строки
для оплаты и проверки связи. Страница показывает вращающийся значок, отправляет
форму сама, без JavaScript оставляет кнопку; повторная кнопка появляется через 4 секунды.
Все эти файлы, включая сегодняшний вариант страницы, лежат вместе в форке.

## Перед установкой

- На машине оператора: Python 3.13, Git, SSH и SCP; Windows — Git Bash либо PowerShell,
  Linux — обычная оболочка. Дополнительные библиотеки Python установщику не нужны.
- На обоих серверах: Linux, доступ SSH без запроса пароля, права на нужные файлы
  и управление службами. Установщик использует обычные `sh`, `tar`, `sha256sum`, `cp`, `chmod`.
- На сервере бота уже работает SoloBot со штатной ЮKassa, Python и зависимостями бота;
  служба systemd запущена. В админке «Модули» включён `inhouse`,
  `YOOKASSA_SBP_ONLY=False`, `USE_NEW_PAYMENT_FLOW` — список. Эти значения оператор
  проверяет в настройках бота: установщик не читает ключи и `config.py`.
  Таблицу `inhouse_yk_links` модуль создаёт сам при запуске; секрет меток тоже создаётся сам.
- На российском сервере уже работает системный Caddy **2.11.1** с доступным API
  перезагрузки. На боте — Caddy **2.9.1** в работающем Docker-контейнере либо
  системный Caddy. Файл контейнера должен быть смонтирован для записи именно
  в `/etc/caddy/Caddyfile`. Другие версии требуют отдельной проверки.
- Домен оплаты указан только в `../settings.py`, `PUBLIC_BASE_URL`.
  Все его записи A/AAAA должны вести на российский сервер; при NAT укажите
  `--ru-public-ip`. Домен бота уже работает по HTTPS, порты 80/443 доступны.
  Блок домена бота в Caddy должен быть отдельным: `domain {` или `https://domain {`.
- Каталог `--web-root` выделен этим четырём файлам; родитель доступен для записи.
  При смене каталога он подставляется также в Caddy. Чужие файлы не удаляются.

## Одна команда

Из этой папки после коммита локальных изменений:

```bash
python install.py check --bot-link https://t.me/ИМЯ_БОТА
python install.py install --bot-link https://t.me/ИМЯ_БОТА
python install.py uninstall
```

Подставьте настоящее латинское имя бота. Значения по умолчанию указывают на нынешние
рабочие серверы; для переезда обязательно укажите новые SSH-имена и пути:

```bash
python install.py install --bot-host NEW_BOT --ru-host NEW_RU --bot-dir /root/Solo_bot --bot-domain bot.example.org --bot-upstream 172.18.0.1:3002 --web-root /var/www/pay-example --bot-link https://t.me/example_bot --copy-module
```

`--copy-module` явно разрешает заменить только `modules/inhouse/`, включая удаление
устаревших файлов. Без него установщик требует чистый форк и только движение Git
вперёд; каждый переносимый коммит проверяется, изменения вне `modules/inhouse/`
отклоняются, даже если позднее они были отменены. Вариант Git переносит
коммиты через SCP без отправки на GitHub. Копирование переносит файлы без тестов.

`check` читает состояние и считает правки, но не создаёт кандидатов, копий и замков,
не проверяет конфигурацию запуском Caddy и ничего не перезапускает.
`install` сохраняет прежние файлы, проверяет каждый кандидат Caddy до записи,
пишет Caddy на месте с сохранением номера файла, перезагружает его и проверяет
новый запуск бота по позиции в журнале. Затем проверяет страницу, запрет GET,
отказ для заведомо испорченной метки и проверку связи. Счета и оплаты не создаёт.
Повторная установка совпадающих файлов не меняет и бота не перезапускает.

## Выключение и удаление

```bash
python install.py disable
python install.py enable
python install.py uninstall
python install.py uninstall --remove-module
```

Локальный выключатель — `modules/inhouse/.yookassa_methods.disabled`, исключённый
из Git собственным `.gitignore`. Он не меняет `settings.py`. Старый модуль до
обновления не понимает этот файл: `disable`/`enable` проверяют поддержку и остановятся.
`enable` не заменяет включение модуля в админке и `FEATURES=True` в исходных настройках.
Удаление убирает наши строки обоих Caddy и только четыре файла страницы;
пустые каталоги удаляются. По умолчанию модуль остаётся выключенным, таблица и
секрет меток остаются. Повторное удаление допустимо.

`--remove-module` удаляет **весь** `inhouse`, в том числе будущие темы:
используйте только если они больше не нужны. В форке сервера удаление отслеживаемых
файлов будет видно Git — это намеренное удаление, обратно ставьте через `--copy-module`.
История Git не переписывается. Секрет в `storage/inhouse/` не читается и не удаляется.

Необязательное удаление таблицы требует отдельного явного указания:

```bash
python install.py uninstall --drop-table --postgres-container POSTGRES --database-name DATABASE --database-user postgres
```

Это только для локального PostgreSQL в Docker с уже настроенным входом без пароля.
Сначала `pg_dump` сохраняет таблицу с правами 600 в `storage/inhouse_yk_links-<id>.sql`,
затем `psql` удаляет её. Если удаление не подтвердилось, установщик проверяет наличие
таблицы и при её исчезновении возвращает её из копии, прежде чем вернуть остальные
части. Копия остаётся и для ручного восстановления через `psql`.
База другого вида этим ключом не поддерживается. Повтор не делает лишнюю копию.

## Параметры и возврат

Все параметры: `python install.py -h`. Кроме показанных выше: `--bot-service`,
`--bot-caddyfile`, `--bot-caddy-container` (пустая строка означает системный Caddy),
`--ru-caddyfile`, `--ru-public-ip`, `--wait-seconds` (1–600), `--restart`.
`--pay-domain` только проверяет совпадение с настройками, не переопределяет домен.

При ошибке файлы страницы, Caddy и скопированный модуль восстанавливаются в обратном
порядке, бот перезапускается в прежнем состоянии. При уже выполненном продвижении
Git сохраняется новый проверенный коммит, а тема выключается; история не переписывается.
Счета, таблицы и созданный при запуске секрет этот возврат не удаляет.
Успешный запуск удаляет временные копии. При ошибке восстановления копии остаются,
сообщение `RESTORE INCOMPLETE` называет сервер и суффикс копии. Для Caddy:
`cat FILE.bak-inhouse-ID > FILE`, затем проверка и перезагрузка Caddy на нужном сервере.
Если оборвалось соединение, сначала восстановите SSH и разберите сохранённые копии.
Замок `/tmp/inhouse-install.lock` удаляйте вручную только убедившись, что другой
установщик не работает. Во время команды не правьте те же файлы вручную.

## Чем проверяем пакет

Ожидания проверок — поручение владельца от 10.10.2026: пустая пара готовых серверов,
повтор без изменений, отказ проверки/перезагрузки с возвратом файлов, удаление.
`tests/test_install_orchestration.py` запускает настоящий установщик через подставные
SSH/SCP, настоящий Bash и настоящие файловые команды внутри временного каталога.
Caddy, Docker, журнал и службы подставные; это проверяет порядок и возврат файлов,
но не выпуск сертификата и работу настоящих служб. На новых пустых серверах нужна
последующая пробная установка с разрешения владельца. Тесты, поднимающие настоящий
Caddy/Chromium, доступны только с `INHOUSE_LOCAL_DEPLOY_TESTS=1` и не входят в обычный запуск.
